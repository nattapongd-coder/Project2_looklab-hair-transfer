# FORME Hair Study v2 — เว็บประเมินทรงผมและจัดการภาพสำหรับแอดมิน

แพ็กนี้มีต้นแบบกดลองและโค้ดเริ่มต้นสำหรับ Google Apps Script + Google Sheets ใช้ Google AI Studio ช่วยปรับหน้าตาต่อได้ หน้า Index.html เมื่อเปิดในเครื่องจะเป็นโหมดสาธิตเท่านั้น เมื่อเปิดผ่าน Apps Script จะใช้ backend จริง ไม่มีผลลัพธ์โมเดลจริงรวมอยู่ในไฟล์นี้

## สิ่งที่ออกแบบไว้

- หน้าเข้าสู่ระบบหน้าเดียว: ผู้เข้าร่วมใช้รหัส 6 หลัก แอดมินใช้รหัสตัวเลข 12 หลัก ระบบตัดสิน role ที่เซิร์ฟเวอร์
- ผู้เข้าร่วมเห็นเฉพาะภาพที่มอบหมายให้ตนเอง โดยไม่รับ model หรือ tuning_variant จากเซิร์ฟเวอร์
- 4 ภาพ: ใบหน้าต้นฉบับ / Reference ทรงผม / Reference สีผม / ผลลัพธ์ แตะขยายได้
- ผลลัพธ์คนละประมาณ 20 ภาพ ทุกภาพมี 6 คำถาม ข้อ 1–5 ให้คะแนน 1–5 และข้อ 6 เลือกช่วงเวลาที่รอได้
- บันทึกเมื่อกด “บันทึกและไปภาพถัดไป” เซิร์ฟเวอร์ยืนยันสำเร็จก่อนเปลี่ยนภาพ การเลือกคะแนนที่ยังไม่กดบันทึกจะยังไม่ถูกเก็บถาวร
- กลับมาต่อด้วยรหัสเดิมได้ และแก้คำตอบแล้วเขียนทับรายการเดิม มี lock กันการสร้างแถวซ้ำ
- ลำดับภาพสุ่มด้วย hash ตามผู้เข้าร่วมและเก็บลำดับเดิมเมื่อกลับมา ไม่เปิดเผยชื่อไฟล์หรือรหัสจริงที่บอกโมเดล
- แอดมินดูจำนวนคนที่ทำครบ ความคืบหน้า ค่าเฉลี่ยรายข้อ แยกโมเดล/การจูน ช่วงเวลารอ คำตอบรายภาพ และส่ง CSV ตามตัวกรอง
- แอดมินอัปโหลดภาพต้นฉบับ ภาพอ้างอิงทั้งสอง และภาพผลลัพธ์ FGAN / Barbershop ผ่านหน้าเว็บได้ เพิ่ม/แก้ไข/ซ่อนชุดภาพได้ และเปลี่ยนรหัสผู้ใช้หรือระงับการเข้าใช้ได้

## ลองต้นแบบ

เปิด Index.html ในเบราว์เซอร์ แล้วกด “ลองหน้าผู้ประเมิน” หรือ “ลองแดชบอร์ด”
รหัสสาธิตผู้ประเมิน 123456 และแอดมิน 999999 ใช้เฉพาะต้นแบบ ตัวเลข สถิติ และภาพวาดเป็นข้อมูลสมมติ ระบบจริงจะไม่ยอมรับรหัสเหล่านี้อัตโนมัติ
การเปลี่ยนแปลงสาธิตอยู่ในหน่วยความจำของแท็บนี้เท่านั้น รีเฟรชหน้าแล้วข้อมูลตัวอย่างเริ่มใหม่ ไม่ส่ง Google Sheets

## ติดตั้งระบบจริง

1. สร้าง Google Sheets ใหม่ให้ผู้วิจัยเป็นเจ้าของ ไม่แชร์ชีตให้ผู้ประเมิน เปิด Extensions → Apps Script
2. วาง Code.gs ลงในไฟล์ Code.gs
3. เพิ่มไฟล์ HTML ชื่อ Index และวาง Index.html ทั้งไฟล์
4. รัน setupResearch_ จาก editor และอนุญาตสิทธิ์ Sheets / Drive ตามที่ Google แสดง ฟังก์ชันนี้สร้างตาราง ไม่ล้างคำตอบเดิม ถ้าหัวตารางชนกันจะหยุดแจ้งชื่อชีต
5. กลับ Sheets จะพบ FS_Participants, FS_Codes, FS_Images, FS_Responses ใช้เมนู FORME ได้หลังเปิดชีตใหม่
6. FS_Codes มีรหัสสุ่ม 40 คนและ ADMIN แจกให้แต่ละคนเฉพาะรหัสของตน เก็บรหัสแอดมินและชีตไว้กับผู้วิจัยเท่านั้น รหัสจริงสุ่มตอนตั้งค่า ไม่ใช้รหัสตัวอย่าง
7. เตรียมภาพจริงที่มีอยู่ ไม่ต้องรันโมเดลใหม่ ภาพใช้ JPG/PNG/WebP ไม่เกิน 2 MB ต่อไฟล์ แนะนำประมาณ 300–800 KB เพื่อโหลดบนมือถือ ภาพจะเก็บใน Google Drive แบบส่วนตัว ผู้ประเมินไม่ต้องมีสิทธิ์ Drive โดยตรง
8. หลัง deploy ให้เข้าด้วยรหัส ADMIN → จัดการชุดภาพ → เพิ่มชุดภาพ เลือกผู้เข้าร่วมและ pair_id อัปโหลดภาพทั้ง 5 ไฟล์ (ต้นฉบับ / ทรงผมอ้างอิง / สีผมอ้างอิง / ผล FGAN / ผล Barbershop) เลือกการจูนและใส่เวลาที่วัดจริงถ้ามี ระบบเติม FS_Images และเก็บ Drive ID ให้อัตโนมัติ ไม่ต้องกรอกใน Sheets เอง หากมีไฟล์บน Drive อยู่แล้วสามารถใส่ FILE ID ใน FS_Images ตามตาราง ไม่ใช้ URL หรือ folder ID
9. ข้ามขั้นตอนตรวจภาพได้จนกว่าจะเพิ่มภาพแล้ว จากนั้นรัน validateImages_ เพื่อตรวจไฟล์ สิทธิ์ คู่ทดลอง และจำนวนภาพ (ไฟล์มากอาจใช้เวลา; ตรวจเป็นชุดก่อนถ้าชนข้อจำกัดการรัน)
10. Deploy → New deployment → Web app → Execute as Me → เลือก audience ให้ผู้เข้าร่วมเข้าถึงได้ เช่น Anyone ถ้าบัญชีอนุญาต → Deploy แล้วใช้ URL ลงท้าย /exec การตั้งค่า audience อาจขึ้นกับนโยบาย Google Workspace
11. ทดสอบจากเบราว์เซอร์อื่นด้วยรหัสผู้เข้าร่วม และแอดมินก่อนแจกจริง เมื่อแก้โค้ดให้ Manage deployments → Edit → New version → Deploy

โค้ดนี้ใช้ HTML Service + google.script.run ให้หน้าเว็บเรียก Apps Script โดยตรง Google AI Studio เป็นเครื่องมือช่วยออกแบบและแก้โค้ด จากนั้นย้าย HTML ไปเผยแพร่ใน Apps Script ไม่ต้องมี API key ของ Gemini เพื่อทำแบบสอบถามนี้
ถ้าจะ host หน้าเว็บแยกใน Google AI Studio/Cloud Run ต้องเปลี่ยน adapter และมี backend gateway ที่ยืนยันสิทธิ์ อย่าย้าย secret ไปไว้ใน frontend และอย่าใช้ fetch(mode:'no-cors') เพื่อเลี่ยงการอ่านผลบันทึก

## โครงสร้างชีต

FS_Participants:
participant_id | login_hash | status

- participant_id: U001–U040
- login_hash: setup สร้างให้อัตโนมัติ ไม่ใส่ plaintext PIN ในช่องนี้
- status: active หรือ disabled; เปลี่ยน disabled จะไม่อนุญาตให้ session เดิมอ่าน/บันทึกต่อ

FS_Codes:
participant_id | login_code

- ใช้แจก PIN เท่านั้น ไม่มี API ฝั่งผู้ประเมินที่อ่านชีตนี้
- แถว ADMIN เป็นรหัสแอดมินจริง 12 หลัก ส่วน hash เก็บใน Script Properties
- เปลี่ยนรหัสแอดมินด้วยการตั้ง ADMIN_LOGIN_HASH ใหม่ผ่านฟังก์ชันภายในที่ใช้ hash_ และอัปเดต FS_Codes ด้วย อย่าเปลี่ยนแค่รหัสข้อความในชีตเพราะระบบตรวจ hash

FS_Images:

| คอลัมน์ | ตัวอย่าง / ความหมาย |
|---|---|
| image_id | IMG_0001 รหัสไม่ซ้ำทั้งโครงการ (frontend ได้รหัส opaque แทน) |
| participant_id | U001 |
| pair_id | C01 คู่เงื่อนไขเดียวกันของผู้เข้าร่วมคนนี้ |
| model | FGAN หรือ Barbershop |
| tuning_variant | V1, V2, V3, V4 |
| original_file_id | ID ภาพต้นฉบับ |
| hair_file_id | ID Reference ทรงผม |
| color_file_id | ID Reference สีผม |
| result_file_id | ID ภาพผลลัพธ์ |
| generation_seconds | เวลาที่วัดจริง หน่วยวินาที หรือเว้นว่างถ้าไม่มีข้อมูล |
| enabled | TRUE |

หนึ่งคู่มีสองแถว FGAN และ Barbershop อย่างละภาพ โดยใช้ original/hair/color เดียวกัน ถ้าคนละเงื่อนไขให้ใช้ pair_id คนละตัว V1–V4 เป็น metadata ไม่ได้สมมติจำนวนภาพต่อการจูนให้เท่ากัน
จำนวนจริงประมาณ 20 ภาพต่อคนจะขึ้นกับภาพที่คุณมอบหมาย ห้ามบังคับสร้าง 40 ภาพต่อคนเพราะมี 4 การจูน ถ้าต้องการเปรียบเทียบการจูนเฉพาะคู่ ให้กำหนด pair_id ที่สะท้อนเงื่อนไขนั้นอย่างถูกต้อง
Reference อาจเปลี่ยนแต่ละผลลัพธ์ ระบบโหลดตามแถว ไม่ตรึง Reference เดิมทุกภาพ

FS_Responses:
participant_id | image_id | q1 | q2 | q3 | q4 | q5 | wait_bin | updated_at

หนึ่งแถวต่อผู้เข้าร่วมและภาพ updated_at เป็น ISO UTC โมเดล การจูน และเวลาจริง lookup จาก FS_Images ไม่รับค่าที่ผู้ประเมินส่งเอง ให้แก้ภาพผ่านหน้าแอดมินหลังเริ่มทดลอง ระบบสร้างเวอร์ชันใหม่และซ่อนเวอร์ชันเดิมโดยไม่เปลี่ยน metadata ของคะแนนเก่า หลีกเลี่ยงแก้ FS_Images หรือเขียนทับไฟล์บน Drive โดยตรง เพราะข้ามระบบเวอร์ชัน

wait_bin เก็บเป็นรหัสประเภท:

| รหัส | คำตอบ |
|---|---|
| 0 | น้อยกว่า 1 นาที |
| 1 | 1–5 นาที |
| 2 | มากกว่า 5–10 นาที |
| 3 | มากกว่า 10–20 นาที |
| 4 | มากกว่า 20–40 นาที |
| 5 | มากกว่า 40 นาที |

ห้ามนำรหัสเหล่านี้ไปคำนวณค่าเฉลี่ยนาที ผู้ที่เลือก 20–40 นาทีไม่ได้ระบุว่าตนยอมรอถึง 40 นาทีแน่นอน จึงสรุปเปอร์เซ็นต์ยอมรอครบ 40 นาทีจากช่วงนี้โดยตรงไม่ได้

## แบบสอบถาม

1. ทรงผมใกล้เคียงกับภาพอ้างอิงมากเพียงใด?
2. สีผมตรงกับภาพอ้างอิงมากเพียงใด?
3. ภาพดูสมจริงและเป็นธรรมชาติมากเพียงใด?
4. ใบหน้ายังคงเหมือนตัวคุณมากเพียงใด?
5. คุณพึงพอใจกับภาพนี้สำหรับการใช้งานจริงมากเพียงใด?
6. หากต้องรอให้ระบบสร้างภาพที่มีคุณภาพเหมือนภาพนี้ คุณยินดีรอได้นานที่สุดเท่าใด?

ข้อ 1–5: 1 น้อยที่สุด / 2 น้อย / 3 ปานกลาง / 4 มาก / 5 มากที่สุด
ข้อ 6: เลือกช่วงเวลา 1 ตัวเลือกต่อภาพ ไม่แสดงเวลารันจริงก่อนตอบ
40 คน × 20 ภาพ = 800 ชุดคำตอบ = 4,800 คำตอบรายข้อ เมื่อครบตามแผน

## การตีความแดชบอร์ด

แสดงค่าเฉลี่ยรายข้อพร้อมจำนวนชุดคำตอบ และเวลาประมวลผลเฉลี่ยจากค่าที่กรอกจริง ข้อ 5 ไม่ใช้ฟิลด์ overall_satisfaction_rating ที่ไม่อยู่ในแบบสอบถามนี้
ไม่ผสมข้อ 6 กับคะแนนคุณภาพ ไม่ประกาศโมเดลชนะทางสถิติจนมีการวิเคราะห์ที่รองรับการประเมินซ้ำในบุคคลและคู่เงื่อนไข
ภาพแนบเดิมพูดถึง Top-3 ซึ่งหมายถึงการเลือกอันดับ 3 อันดับ หากต้องการ “สัดส่วนถูกเลือก Top-3” ต้องเพิ่มขั้นตอนจัดอันดับจริง แพ็กนี้เป็นการให้คะแนนรายภาพ จึงไม่เรียกคะแนน 3–5 ว่า Top-3 ไม่สร้างเปอร์เซ็นต์ถูกเลือกขึ้นเอง
คำตอบหลายภาพของคนเดียวกันไม่เป็นอิสระ 800 ชุดคำตอบไม่ได้เท่ากับผู้เข้าร่วมอิสระ 800 คน
แดชบอร์ดรุ่นนี้แสดงผู้เข้าร่วม active และภาพ enabled เท่านั้น คำตอบเดิมยังอยู่ใน Sheets แม้ปิดใช้งานคนหรือภาพ

## ขอบเขตและตรวจรับก่อนใช้งาน

ยังไม่ได้ deploy ไปบัญชี Google หรือทดสอบสิทธิ์กับ Drive ของคุณ ต้องอัปโหลดภาพจริงผ่านหน้าแอดมิน และทดสอบบน /exec ก่อนใช้งานจริง
ตัวโค้ดใช้ session token ในหน่วยความจำของหน้าเว็บและ Script Cache หมดอายุสูงสุด 6 ชั่วโมง Cache อาจหายก่อนกำหนดได้ ให้ล็อกอินใหม่ คะแนนที่บันทึกยังอยู่ใน Sheets
มี rate limit การเข้าสู่ระบบทั้งแอปและตามรหัส แต่ระบบ PIN 6 หลักเป็นกลไกเข้าถึงสำหรับการทดลองขนาดเล็ก ไม่ใช่การยืนยันตัวบุคคลระดับบัญชีจริง ไม่แชร์ PIN หรือ Sheets/Drive กับทุกคน

รายการตรวจรับ:
- U001 ไม่เห็นภาพ U002 และส่งรหัสภาพของ U002 แล้วถูกปฏิเสธ
- token ของผู้เข้าร่วมเรียก getDashboard แล้วถูกปฏิเสธ
- network response ของผู้เข้าร่วมไม่มี model/tuning_variant/Drive ID/ชื่อไฟล์
- ข้อไม่ครบ / คะแนน 0 หรือ 6 / wait_bin นอก 0–5 บันทึกไม่ได้
- ส่งคำตอบเดิมซ้ำยังมีหนึ่งแถว เมื่อย้อนแก้คะแนนแล้วแถวเดิมเปลี่ยน
- ปิดเว็บแล้วใช้รหัสเดิม ได้คะแนนที่เคยบันทึกและลำดับเดิม
- บันทึกครบ 20 ภาพแล้วขึ้นหน้าขอบคุณ
- คะแนนและจำนวนแถวใน dashboard/CSV ตรงกับ Sheets
- ทดสอบบนมือถือและใน Safari iPad รวมการขยายภาพและการดาวน์โหลด CSV
- อินเทอร์เน็ตหลุดตอนบันทึก ต้องไม่ขึ้นว่าสำเร็จหรือเปลี่ยนภาพ ถ้าเซิร์ฟเวอร์บันทึกแล้วแต่ browser ไม่ได้รับผล สามารถกดซ้ำได้โดยไม่สร้างแถวซ้ำ

### จัดการชุดภาพ
- เพิ่มชุดภาพ: เลือก U001–U040 ตั้งรหัสคู่ เช่น C01 เลือกไฟล์ 5 ประเภทพร้อมกัน หรือค่อยเลือกทีละไฟล์ จากนั้นกดบันทึก ระบบส่งไฟล์ไป Drive หลังยืนยันตัวแอดมิน ไม่รัน HairFastGAN / Barbershop ใหม่
- แต่ละคู่ทดลองมี original/hair/color เดียวกันและผลลัพธ์สองโมเดล แอดมินเลือกการจูน V1–V4 แยกแต่ละโมเดลได้ หากนำเข้าแบบหนึ่งโมเดลไว้ก่อน สามารถเข้าแก้และเติมอีกโมเดลในชุดนั้นได้
- “แก้ไขภาพ” โหลดภาพเดิมเพื่อดู เลือกไฟล์ใหม่เฉพาะช่องที่ต้องการเปลี่ยน ช่องอื่นใช้ภาพเดิม แก้การจูนและเวลาที่วัดจริงได้ (เวลาไม่จำเป็นต้องกรอกถ้าไม่รู้)
- เปลี่ยนภาพหรือเงื่อนไขเดิม จะสร้างรหัสภาพใหม่ทั้งคู่และซ่อนสองแถวเก่า แม้ยังไม่มีคะแนน เพื่อไม่รับคะแนนจากหน้าเก่าที่เปิดค้างอยู่ ผู้ใช้ต้องกดโหลดรายการใหม่หากรายการเปลี่ยน
- หากเปลี่ยนภาพที่มีคะแนนแล้ว คะแนนเก่าอยู่ใน FS_Responses และดูผ่านเมนู “ประวัติคำตอบ” ได้ ภาพใหม่เริ่มประเมินใหม่ ไม่ใช้คะแนนเดิมแทน
- “ซ่อนชุด” / “เปิดชุด” เปลี่ยนการมองเห็นทั้งสองโมเดล ไม่มีการลบไฟล์หรือคะแนนถาวร เปิดเวอร์ชันเก่าไม่ได้ถ้ามีเวอร์ชันอื่นในคู่เดียวกันเปิดอยู่
- ตัวแก้ไขแสดงเวอร์ชันเปิดใช้อยู่ หรือเวอร์ชันล่าสุดที่ซ่อน หากต้องวิเคราะห์เวอร์ชันเก่าใช้เมนูประวัติและ FS_Images ประกอบ
- ไฟล์ที่อัปโหลดเก็บในโฟลเดอร์ส่วนตัวชื่อ FORME Hair Study Images โดย ID อยู่ใน Script Property FS_DRIVE_FOLDER_ID ถ้าบัญชีอนุญาต Drive ในรอบแรกไม่ครบ Google อาจให้ยืนยันสิทธิ์เพิ่มจาก editor หลังแก้โค้ด
- หากอัปโหลดเสร็จแล้วบันทึกชุดไม่สำเร็จ กดซ้ำได้โดยใช้ไฟล์ที่อัปโหลดแล้วในแท็บนั้น ไฟล์ที่ยังไม่ผูกกับชุดอาจค้างใน Drive ให้เจ้าของล้างเมื่อแน่ใจว่าไม่ใช้ ระบบไม่ลบภาพของผู้วิจัยอัตโนมัติ

### จัดการผู้ใช้
- เลือก “เปลี่ยนรหัส 6 หลัก” → กรอกหรือกดสุ่ม → บันทึก รหัสต้องไม่ซ้ำกับคนอื่น ระบบอัปเดตทั้ง login_hash และ FS_Codes ให้
- เปลี่ยนรหัสแล้ว session เก่าถูกปฏิเสธตั้งแต่การเรียก backend ครั้งถัดไป เจ้าของรหัสล็อกอินใหม่ด้วยรหัสใหม่ คะแนนเดิมไม่หาย
- “ระงับการเข้าใช้” ห้ามอ่าน/บันทึกต่อ เปิดใช้คืนได้ ข้อมูลและภาพยังอยู่
- เมนูนี้เปลี่ยนรหัสผู้เข้าร่วม ไม่ใช่รหัสแอดมิน

### ประวัติคำตอบ
- รายการคำตอบของภาพที่ซ่อนหรือผู้เข้าร่วมที่ระงับจะอยู่เมนูนี้ กรองได้และ CSV ส่งออกเฉพาะรายการของแท็บนี้
- Dashboard ภาพรวมใช้เฉพาะภาพ enabled และคน active เพื่อไม่ผสมภาพเก่ากับเวอร์ชันใหม่ ดังนั้นถ้าเปลี่ยนภาพ จำนวนทำครบ/คำตอบในชุดปัจจุบันอาจลดลงจนประเมินภาพใหม่ครบ

## เกี่ยวกับ ZIP เก่าที่แนบ

HairFastGAN_Feedback_Setup (1).zip เป็น flow /feedback ผ่าน Python/FastAPI/Colab และมีสคีมาคำถามคนละชุดกับแบบประเมินรายภาพนี้ รุ่นนี้ใช้ frontend → google.script.run → Apps Script → Sheets/Drive โดยตรง ไม่ใช้ notebook, backend Python, ngrok หรือ endpoint /generate
แนะนำสร้าง Google Sheets ใหม่สำหรับการทดลองนี้ เพื่อไม่ชนหัวตาราง Feedback เดิม ข้อมูล Feedback เก่าไม่ได้ถูกย้ายหรือแปลงเป็น 6 ข้ออัตโนมัติ เก็บข้อมูลเก่าไว้แยกเดิมได้ ไม่ต้องวาง Code.gs ทั้งสองรุ่นในโปรเจกต์เดียวกัน เพราะจะมี doGet ซ้ำ
หากอัปเกรดจาก FORME รุ่นก่อน ให้แทนที่ Code.gs และ Index ด้วยไฟล์รุ่นนี้ แล้ว deploy new version ใช้ชีต FS_* เดิมได้โดยไม่เปลี่ยน header รหัสเดิมและคะแนนเดิมอยู่ครบ session เดิมจะให้ล็อกอินใหม่เพื่อใช้การตรวจรหัสเวอร์ชันล่าสุด
